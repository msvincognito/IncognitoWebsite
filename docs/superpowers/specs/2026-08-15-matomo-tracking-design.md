# Matomo Tracking Integration Design

## Goal

Track page views and outbound link activity across every public website route using the supplied self-hosted Matomo instance.

## Context

The website is a statically generated Astro site. Every route uses `src/layouts/BaseLayout.astro`, and navigation performs normal document loads rather than client-side SPA route changes. Matomo can therefore track each page with its standard asynchronous JavaScript snippet; SPA-specific route listeners are unnecessary and could create duplicate page views.

## Design

Add the supplied Matomo tracking snippet once in the `<head>` of `BaseLayout.astro`. The tracker will:

- initialize `window._paq`;
- record one page view per document load;
- enable link tracking;
- load `//analytics.msvincognito.nl/matomo.js` asynchronously;
- send data to `//analytics.msvincognito.nl/matomo.php`; and
- associate tracking data with Matomo site ID `1`.

Because all current routes use `BaseLayout`, this covers the homepage, content pages, the Intro Camp terms page, and the 404 page without route-specific duplication.

No community Astro integration will be added. The available `astro-matomo` package primarily adds configuration and SPA/View Transitions support that this site does not currently need. Keeping the standard Matomo snippet in the shared layout avoids an unnecessary runtime dependency and preserves the exact tracking configuration generated by the site's Matomo installation.

## Privacy and Failure Behavior

This change uses the tracking behavior supplied by the user without adding cookie-consent, cookie-disabling, or environment-gating behavior. If the analytics host is unavailable or the script is blocked, it loads asynchronously and must not prevent the website from rendering or functioning.

## Verification

Before implementation, add a focused automated check that fails while the shared layout lacks the Matomo host, tracker endpoint, script endpoint, site ID, page-view call, and link-tracking call. After implementation:

1. Run the focused check and confirm it passes.
2. Build the Astro site.
3. Inspect representative generated pages to confirm each contains exactly one Matomo initialization.
